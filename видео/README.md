# final-video: как мы собираем ролики

Вертикальный чёрно-белый ролик 1080×1920, 30 fps, **80–100 секунд**: один закон или факт, история на понятном примере, голос клона, человечки-контуры, заголовок-плашка в каждом кадре.

Рецепт собран из разбора ста роликов larkin.life (`research/larkin-life/`), эталона «Идеальный вариант/» и сборки роликов «Принцип Питера», «Рингельман», «Прибавка».

**Коротко, весь путь от идеи до видео:**

1. **Идея** (раздел 0): берём тему, которая доказала спрос у другого автора, но которой у него нет. Факты сверяем.
2. **Текст** (раздел 4): своими словами, по скелету, с проверкой `script_check.py`.
3. **Озвучка** (раздел 5): `voiceover.py`, клон голоса друга, ударения слушает человек.
4. **Видео** (разделы 6–7): эпизод в `what-if-studio`, сцены по таймингам слов, рендер 1080×1920.

Метки в тексте: **замерено** (число из данных), **решение** (выбрали мы), **рекомендация** (логично, но на 80–100 секундах ещё не проверялось).

## 0. Идеи: как мы их собираем

**Принцип.** Идея это не «интересная тема», а тема, у которой уже доказан спрос, но у конкретного автора её ещё нет. Берём приём и устройство ролика, а тему, текст, рисунок и голос делаем свои.

### Шаги

1. **Выборка.** 100 роликов larkin.life за 2–8 ноября 2026. Таблица `research/larkin-life/reels-table.csv` (колонки `shortcode, url, date, views, likes, comments, duration_s, caption_head`) и `reels.json`. Для каждого скачанного ролика есть папка `research/larkin-life/reels/ID/`: видео, лист кадров `sheet.jpg`, расшифровка `transcript.txt`. Список ссылок лежит в `batch2-urls.txt`, `batch3-urls.txt`.
2. **Ранжируем по просмотрам, не по лайкам.** Замерено: медиана 70 тыс. просмотров, всего 17,9 млн, **топ-10 роликов дают 50 % всех просмотров**. Значит, смотрим на хиты, а не на «среднее по серии».
3. **Расшифровываем.** `faster-whisper large-v3` на CUDA, около 10 секунд на ролик. Нужен путь к `cublas64_12.dll` из `voice-clone\venv\Lib\site-packages\torch\lib` в `PATH`, запускать из `voice-clone\venv-text`. Вывод писать в файл с кодировкой UTF-8: консоль Windows ломает кириллицу.
   ```python
   from faster_whisper import WhisperModel
   m = WhisperModel("large-v3", device="cuda", compute_type="float16")
   segs, _ = m.transcribe("ролик.mp4", language="ru", vad_filter=True)
   open("transcript.txt", "w", encoding="utf-8").write("\n".join(f"[{s.start:6.1f}-{s.end:6.1f}] {s.text.strip()}" for s in segs))
   ```
4. **Выясняем, что сработало** (`research/larkin-life/ANALYSIS.md`): хук-провокация про зрителя, серия с номером части, имя и год в каждом абзаце, масштаб в знакомое, финал переворачивает хук.
5. **Ищем, чего у автора нет.** Прогоняем кандидата по 100 подписям и 70 расшифровкам по ключевым словам (так проверялись Абилин, Даннинг, лимон, лотерея). Нет совпадений и тема близка к хитам: подходит.
6. **Карточка идеи.** Обещание зрителю, 12 битов текста с заголовком и рисунком на каждый, факты со ссылками, что вымышлено, что `[проверить]`. Образец: `research/larkin-life/IDEAS-top3.md`.
7. **Сверка фактов** по первоисточнику или обзору до записи голоса. Вымышленного героя и его суммы отмечаем как вымысел.

## 2. Параметры формата

| Параметр | Значение | Откуда |
|---|---|---|
| Длина | 80–100 с | **решение** (у автора медиана 110 с, диапазон 82–216 с, 80% роликов 93–149 с; **замерено** по `reels.json`) |
| Слов | примерно 215–270 | **замерено**: наш голос идёт 2,7 слова в секунду (эталон 80 слов за 28,7 с, «Прибавка» 85 слов за 31,9 с) |
| Планов | 25–35, в среднем 2,5–3,5 с | **рекомендация**: в эталоне 13 планов на 28,6 с (2,3 с), у автора кадр меняется каждые 3–6 с |
| Склейки | только жёсткие, новая мысль = новый кадр | **решение**, эталон |
| Цвет | чёрное и белое, акцент заливкой чернью | **решение**, эталон |
| Заголовок в кадре | 2–6 слов, читается без звука | **решение**, эталон |
| Голос | клон F5-TTS, около −15 LUFS, без пауз длиннее 0,3 с | **решение**, эталон |
| Конец | уход в белое с концом последнего слова, после слова не больше 0,5 с тишины | **решение**, эталон |

Важное правило: **любой ролик сначала собирается тестом на ~15 секунд**, полный рендер только после одобрения теста.

## 3. Конвейер по шагам

1. **Тема и факты.** Один закон, исследование или история с реальными именами, годами и числами. Каждый факт сверить по обзору или первоисточнику, непроверенное пометить `[проверить]`. Тему брать своей, чужие ролики близко к тексту не пересказывать (`research/larkin-life/IDEAS-top3.md`).
2. **Текст** по скелету из раздела 4. Показать пользователю вместе с источниками и ждать одобрения.
3. **Проверка текста.**
   ```
   python "C:\Users\daatva\.claude\skills\humanizer-ru-novella\scripts\script_check.py" файл.txt --minutes 1.5 --wpm 160
   ```
   FAIL чинить, WARN смотреть глазами. Для коротких фраз WARN «доля коротких» допустим.
4. **Озвучка** (раздел 5). Ударения слушает человек.
5. **Тайминги.** Из `best_words.json` взять время слов, по ним расставить границы планов и моменты внутри планов (раздел 6).
6. **Эпизод.** Скопировать готовую папку эпизода, переименовать, добавить в `src/episodes/index.ts`, положить `voice.wav` в `public\ТЕМА\`.
7. **Сцены** в `shots.tsx`: по одной на фразу или смысловой блок (раздел 6).
8. **Тест ~15 с:** границы и `TOTAL` на первых 6–8 фразах, остальное закомментировать. Рендер раскадровки, потом видео, проверка кадров и звука, показать пользователю.
9. **После одобрения:** сцены на остальные фразы, `TOTAL` на весь текст, полный рендер, снова проверка и чек-лист.
10. **Выдача:** копия в `для Ютуба\` или `для Инстаграма\`, список сомнительных мест (ударения, факты, голос).

## 4. Текст на 80–100 секунд

### Скелет

Основа: 12 битов эталона (хук, имя закона, герой, поворот, последствия, тупик, формула, масштаб, доказательство, абсурдная деталь, обращение к зрителю, закольцовка). Для 80–100 с структуру автора добавляем в середину.

| Блок | Что делает | Доля времени |
|---|---|---|
| Хук | Обвинение зрителя или парадокс, ключевое слово повторится в финале | 0–5 с |
| Имя и дата | «Принцип Питера, 69-й год» | 5–10 с |
| История | Один понятный герой, поворот, три быстрые детали последствий | 10–35 с |
| «Вот ещё» | 2–3 примера подряд, каждый короче предыдущего | 35–55 с |
| Доказательство | Кто, когда, что посчитал, одно число | 55–70 с |
| Абсурд или твист | Смешная деталь, которая переворачивает вывод | 70–80 с |
| Практический совет | Что зрителю сделать завтра | 80–90 с |
| Закольцовка | Слово из хука с новым смыслом | последние 5–10 с |

Это **рекомендация**: блоки «вот ещё» и «практический совет» взяты из структуры автора (`ANALYSIS.md`), на 80–100 с в нашем стиле мы их ещё не собирали.

### Правила

- **Мат: 4–6 раз на ролик, обязательно.** Только там, где он реально усиливает эмоцию: хук-обвинение, «ну и пиздец» после цифры, злость героя, финальный удар. Как вставное слово посреди фразы («блядь», «сука» после подлежащего) или усилитель («нахуй», «хуйня», «пиздец»). Не в каждой фразе и не для галочки. На экране в заголовках мата нет, он только в голосе. Образец: `озвучка/texts/pribavka80.txt` (чистовик: `видео/озвучка/texts/`).
- Первое слово лучше «твой», «ты» или неожиданный предмет. Без «привет», «сегодня расскажу», «вы знали».
- Фразы 3–9 слов. Если не читается на одном выдохе, режь.
- Конкретика в каждом блоке: имя, год, профессия, число. Не «учёные доказали».
- Масштаб переводим в знакомое («минус Саратов каждый год»).
- Быт вместо абстракции: шторы, чат, созвон на 12 человек, кофе по триста.
- Тройки только в блоке последствий.
- Вымышленного героя называем и ведём через весь ролик (Саша, Вася). Числа вокруг него вымысел, и в источниках это отмечаем.
- Финал отвечает на хук.
- Реплика-повтор для ударения: допускается, но один приём не чаще трёх раз.
- Чужие названия и бренды из голоса автора не копируем.

### Как писать числа

В тексте можно цифрами (`69-й`, `2010-м`, `30 000`), конвейер переведёт их в слова.

## 5. Озвучка

Голос: локальный клон F5-TTS, образец `voices\friend` (модель Misha24-10 v4_winter).

**Монолитный режим (по умолчанию с 09.11.2026).** Каждое предложение генерируется отдельно со скоростью 1,0, для него подбирается дубль без обрыва в конце (F5 иногда режет последнее слово), стык между предложениями 0,06 с с затуханием 30 мс. Паузы пользователь не хочет, поэтому вставлять их не надо. Старый режим (весь текст одним проходом, скорость 0,9) остался под флагом `--whole`.

```
cd C:\Users\daatva\voice-clone
venv\Scripts\python.exe voiceover.py texts\ТЕМА.txt --name ТЕМА
```

Конвейер: числа словами → ударения (`silero-stress`, правки из `stress_dict.txt`, второе мнение RUAccent) → 3 дубля всего текста, в каждом по предложению с отбором дубля без обрыва → сверка с текстом через faster-whisper → выбор лучшего → −15 LUFS. Компрессии и эквалайзера нет: на слух пользователь выбрал вариант без обработки. Результат лежит в `out\ТЕМА\`.

**Что мы узнали про голос (замерено на тексте «Рингельман», 30 с):**

- У старого голоса не было пауз вообще (одна пауза за 30 с) и провалы тона до −16 полутонов, у живого образца около ±5. Обрывы слов были на 5 из 11 предложений: звук в конце оставался на полной громкости.
- Скорость 0,9 растягивала звуки. На 1,0 разброс тона 3,2–3,4 полутона, у живого образца 3,4. На 1,08 терялись слова.
- Вариант с настоящими паузами между предложениями пользователь отверг.
- «Все» silero читал как «всё»: в `stress_dict.txt` добавлено `вс+е`. Если в тексте «все» написано вместо «всё» без точек, прочтётся «все».
- GPU делят с другими процессами. При сбое CUDA конвейер сам повторяет попытку до 8 раз.
- Потолок «живости» задаёт образец голоса: сейчас это один отрывок 11,7 с в одной интонации. Следующий шаг: 1–2 минуты речи друга с разными эмоциями, и подбирать образец под каждую реплику.

Что смотреть после запуска:

- `disputed.txt`: слова, где два алгоритма разошлись. Послушать на слух. Неверное слово добавить в `stress_dict.txt` (форма со знаком `+`, по одной на строку) и запустить заново.
- `report.json`: длительность, `match`, `gaps`, `diff`. Расхождения вида «60 → шестьдесят й» бывают от разбивки слов в распознавании и на звук не влияют.

### Если конвейер упал после дублей

Так было на «Прибавке»: три дубля сгенерировались, а `best.wav` не появился (причину падения мы не выяснили). Шаги, которые ещё нужны, запускаются отдельно:

```
cd C:\Users\daatva\voice-clone
venv-text\Scripts\python.exe text_tools.py check out\ТЕМА out\ТЕМА\take_1.wav out\ТЕМА\take_2.wav out\ТЕМА\take_3.wav
```

Затем взять `best` из `out\ТЕМА\report.json` и:

```
ffmpeg -v error -y -i out\ТЕМА\take_1.wav -af "loudnorm=I=-15:TP=-1.5:LRA=11" -ar 48000 out\ТЕМА\best.wav
copy out\ТЕМА\take_1.json out\ТЕМА\best_words.json
```

(вместо `take_1` подставить лучший дубль). Сообщения `NativeCommandError` в PowerShell 5.1 на предупреждения Python в stderr ошибкой конвейера не являются: смотри, появился ли `best.wav`.

### Проверено на «Прибавке 80» (249 слов)

Конвейер отработал целиком без падения: три дубля по 84 с, совпадение с текстом 0,95–0,97, пауз длиннее 0,3 с нет. На слух не слушалось. Нормы длины: 228 слов дали 76,8 с (мало), 249 слов дали 84,6 с. Для 80–100 с брать 245–290 слов. Мат в словарь ударений добавлять: `нах+уй`, `хуйн+я`. Если дубли поплывут, озвучивать по частям (по 6–8 фраз) и склеивать с учётом времени слов.

**Тайминги скриптом.** Для 37 планов границы выписаны не руками: скрипт по `best_words.json` выравнивает слова текста с распознанными (`difflib`) и пишет `timing.ts` (`PLANS`, `T`, `TOTAL`). У плана задаётся первое слово его фразы и слова-события внутри (`T[план][ключ]`, кадры от начала плана). Скрипт лежал в рабочей папке сессии, в проект не вошёл: восстановить по этому описанию.

**Мат.** У автора (замерено по 81 расшифровке): 3–6 раз на ролик, как вставное слово («блядь» посреди фразы, «сука» после подлежащего), как усилитель («нахуй», «хуйня», «пиздец») и в обвинении зрителю. В хуке допустим. В заголовках на экране мата нет, он только в голосе.

## 6. Раскадровка, тайминги и сцены

### Тайминги из `best_words.json`

Формат: список `[начало_с, конец_с, "слово"]`. Кадр = секунды × 30.

- Новый план начинается на **первом слове фразы**, конец плана = начало следующего.
- Моменты внутри плана = (время слова − начало плана) × 30. Например, штамп на слове «столько» или книга на слове «Паркинсона».
- `TOTAL` = кадр конца последнего слова + 12–15, белый уход (`FADE`) начинается с концом последнего слова.
- Тестовая версия с обрезкой: `<Audio ... endAt={кадр конца слова + 2} />`, иначе в конец прорвётся начало следующей фразы.

### Сцены

Сцена = компонент в `shots.tsx`: `<Sheet>` (бумага, крапинки, дрожь линии) → `<Head lines={[...]}>` → рисунок → штамп или подпись. Внутри сцены время считается кадрами от её начала (`useCurrentFrame()`).

Готовые детали из `piter-bw/shots.tsx` (экспортируются): `Sheet`, `Tx`, `Head`, `Draw`, `Pop`, `Ground`, `Stamp`, `Man`, `Specs`, `Tash`, `Car`, `Confetti`, `Check`, константы `W`, `H`, `G`. Из `lines/kit`: `Clock`, `Cloud`, `INK`, `PAPER`. Остальные детали (`Gear`, `Wrench`, `Smoke`, `Boss`) там же, но не экспортированы. Кастомные предметы эпизодов (мешок, купюра, чашка, телефон в `pribavka-bw`; канат, ноутбук в `ringelman-bw`) лежат в их `shots.tsx` и копируются оттуда.

Человечек `Man`: параметры `x`, `y`, `s`, `flip`, `mouth`, `eyes`, `brow`, `hair`, `la`/`ra`, `seed`, `bob`. Подробности в `Идеальный вариант\ИНСТРУКЦИЯ.md`, раздел 3.

### Правила кадра

- Нижние 300–350 px закрывает интерфейс Reels: там только земля и штриховка.
- Заголовок на 2–6 слов, сжимает мысль, не дублирует голос дословно.
- Хотя бы один кадр с толпой и один с шуткой в рисунке (абстракция рисуется буквально).
- В каждом кадре что-то движется: пар, монеты, стрелки, конфетти.
- Элемент появляется ровно на своём слове (`Pop`, `Draw`, `Stamp`).
- Подписи не ставим рядом с осью или линией графика, подпись у оси читается как название оси.
- Штамп не перекрывает стрелки и героя; ширина штампа = `число букв × размер × 0,56 + 70`.
- Текст в пузыре проверять по ширине: размер 60–70 для 16 символов в пузыре шириной около 500 px.
- Масштаб `Man` 1,5–1,75 для главного героя, толпа 0,75–0,9.

## 7. Рендер и проверка

Все команды из папки `what-if-studio`.

**Студия (по желанию):**

```
npx remotion studio src/index.ts --port 3430
```

**Раскадровка** (один кадр на план):

```
npx remotion render src/index.ts ИМЯBoard out/ТЕМА/b --sequence --image-format=png
```

Склеить в лист и посмотреть:

```
ffmpeg -v error -y -framerate 1 -start_number 0 -i out\ТЕМА\b\element-%d.png -vf "scale=360:640,tile=4x2" -frames:v 1 out\ТЕМА\board.png
```

**Видео:**

```
npx remotion render src/index.ts ИМЯ out/ТЕМА/ТЕМА.mp4
```

`ИМЯ` это `id` из `index.tsx` эпизода (например `PribavkaBw`).

**Проверка кадров на словах:** вынуть кадры на ключевых словах в лист:

```
ffmpeg -v error -y -i out\ТЕМА\ТЕМА.mp4 -vf "select='eq(n\,80)+eq(n\,125)',scale=360:640,tile=4x1" -frames:v 1 -fps_mode passthrough out\ТЕМА\frames.png
```

(флаг `-vsync` в нашей версии ffmpeg не работает, использовать `-fps_mode passthrough`).

**Проверка звука:**

```
ffmpeg -hide_banner -i out\ТЕМА\ТЕМА.mp4 -af loudnorm=I=-15:print_format=summary -vn -f null NUL
ffmpeg -hide_banner -ss ВРЕМЯ_ПОСЛЕ_ПОСЛЕДНЕГО_СЛОВА -i out\ТЕМА\ТЕМА.mp4 -af volumedetect -vn -f null NUL
```

Первая команда даёт громкость (цель около −15 LUFS), вторая проверяет, что после слова тихо.

При отправке файла пользователю через `SendUserFile` использовать **абсолютный путь**: относительный считается от текущей папки сессии.

## 9. Что не проверено

- Скелет на 80–100 с собран на «Прибавке 80» (84,9 с, 37 планов, `what-if-studio/out/pribavka80/pribavka80.mp4`). Реакции зрителей на такую длину и на мат нет, это гипотеза.
- Озвучка на 250 слов собрана и проверена по логу (раздел 5), на слух не проверена.
- Время слов от `faster-whisper` приблизительное: границы планов иногда сдвигаются на пару кадров, в тесте это не мешало.
- Ударения, например «подняли» (подн+яли или п+однали), решает только человек на слух.
- Голос клонирован с друга: для публичного канала нужно его согласие, лицензии модели для монетизации не проверены.
- Рисунок эталона из той же семьи, что у ТО «420» (белый лист, крапинки, контурные человечки). Чтобы не повторить обвинения, которые получает larkin.life, нужна своя заметная деталь. Голос и шутки в стиле 420 не копировать.
- Не подтверждено, что нужна именно длина 80–100 с: это решение пользователя на основе длин автора, а не результат проверки на нашей аудитории.
